# AFO — σελίδα πώλησης (ελληνικά)

Μονοσέλιδο site για την πώληση της μπάλας πυρόσβεσης **AFO / Auto Fire Off** σε ελληνικό κοινό,
χτισμένο για μετατροπή (conversion). Ένα αρχείο, χωρίς build, χωρίς εξαρτήσεις: `index.html`.

## Προεπισκόπηση

```bash
python3 -m http.server 8080 --directory sites/afo
# ή
npx serve sites/afo
```

## Τι κάνει τη σελίδα να πουλάει

| Στοιχείο | Γιατί |
| --- | --- |
| Προσφορά, τιμή και CTA πάνω από το fold | ο επισκέπτης ξέρει τι αγοράζει και πόσο κάνει χωρίς scroll |
| Sticky bar με πληρωτέο ποσό | το CTA ακολουθεί σε κάθε ύψος σελίδας, εμφανίζεται μετά το hero και κρύβεται μέσα στη φόρμα |
| Φόρμα 5 πεδίων | email, ΑΦΜ και σημείωση είναι κρυφά πίσω από «+» — λιγότερα πεδία, λιγότερες εγκαταλείψεις |
| Πληρωμή με κάρτα, σε ξεχωριστό βήμα | η φόρμα ζητά μόνο διεύθυνση· τα στοιχεία κάρτας μπαίνουν στη σελίδα της τράπεζας (3-D Secure), όχι εδώ |
| Πίνακας σύγκρισης με πυροσβεστήρα | απαντά στη #1 αντίρρηση: «έχω ήδη πυροσβεστήρα» |
| Πλαίσια εγγύησης δίπλα στο κουμπί | 14 ημέρες, εγγύηση 5 ετών, χωρίς κάρτα — άρση ρίσκου τη στιγμή της απόφασης |
| Βίντεο ή κινούμενη επίδειξη στο «Πώς λειτουργεί» | δείχνει τον μηχανισμό σε κίνηση· η θέση δέχεται δικό σας MP4 ή YouTube (`VIDEO`), αλλιώς παίζει σχηματική απεικόνιση |
| Gallery προϊόντος με 4 όψεις | προϊόν, τοποθέτηση, μέγεθος, περιεχόμενα συσκευασίας — οι τέσσερις εικόνες που ζητά ο αγοραστής πριν αποφασίσει |
| Autosave φόρμας (localStorage) | αν φύγει και γυρίσει, τα στοιχεία είναι εκεί |
| Events για GA4 / Meta Pixel | `view_item`, `select_item`, `begin_checkout`, `purchase_intent`, `form_error` |

Σκόπιμα **δεν** μπήκαν: ψεύτικα «3 άτομα βλέπουν τώρα», ψεύτικα αποθέματα, διαγραμμένες τιμές
που δεν ίσχυσαν ποτέ, εφευρεμένες κριτικές. Απαγορεύονται από την Οδηγία (ΕΕ) 2019/2161
(Omnibus) και επισύρουν πρόστιμα από τη ΓΓ Εμπορίου.

## Τι πρέπει να αλλάξετε πριν πάει ζωντανά

| Πού | Τι |
| --- | --- |
| `SHOP` (αρχή του `<script>`) | επωνυμία, email, μεταφορικά, όριο δωρεάν αποστολής |
| `PAYMENT.checkoutUrl` | **υποχρεωτικό**: ο σύνδεσμος πληρωμής του παρόχου σας (Stripe Payment Link, Viva Smart Checkout, Everypay, e-Commerce τράπεζας). Όσο είναι `null`, ο πελάτης βλέπει σημείωση αντί για κουμπί πληρωμής |
| `PACKS` | τιμές πακέτων. Το `compareAt` (διαγραμμένη τιμή) μπαίνει μόνο αν ίσχυσε πραγματικά τις τελευταίες 30 ημέρες |
| `REVIEWS` | **μόνο πραγματικές κριτικές** πελατών σας. Άδειο = εμφανίζονται κενές θέσεις με σημείωση· αν δεν έχετε, σβήστε την ενότητα `#kritikes` |
| `ORDER_ENDPOINT` | URL backend ή υπηρεσίας φορμών· όσο είναι `null`, η φόρμα ετοιμάζει την παραγγελία ως email |
| `<footer>` + πλαίσιο «Σημείωση για τον πωλητή» | επωνυμία, έδρα, ΑΦΜ, ΔΟΥ, ΓΕΜΗ και email επικοινωνίας (ΠΔ 131/2003) — και μετά **σβήστε το πλαίσιο** |
| `VIDEO` | το βίντεό σας: `youtubeId` ή `src` (οδηγίες λήψης και ασφάλειας: `videos/README.md`). Όσο είναι `null`, παίζει η κινούμενη σχηματική απεικόνιση |
| `PHOTOS` | οι φωτογραφίες του gallery. Βάλτε τα αρχεία στον φάκελο `photos/` (οδηγίες και λίστα λήψεων: `photos/README.md`). Όπου μένει `null`, δείχνει τη σχεδιαστική απεικόνιση |

## Επόμενα βήματα που ανεβάζουν κι άλλο τη μετατροπή

1. **Πραγματικές φωτογραφίες** στο gallery (δείτε `photos/README.md`) και, ιδανικά, **βίντεο 15
   δευτερολέπτων** με πραγματική ενεργοποίηση. Είναι τα στοιχεία που πείθουν πιο γρήγορα από κάθε κείμενο.
2. **Πραγματικές κριτικές** με φωτογραφία τοποθέτησης από πελάτες.
3. **Backend παραγγελιών** (`ORDER_ENDPOINT`) που καταχωρεί τη διεύθυνση πριν την πληρωμή, ώστε να
   ξέρετε ποιος εγκατέλειψε στο βήμα της κάρτας και να του στείλετε υπενθύμιση με email.
4. **Ταχύτητα**: οι γραμματοσειρές έρχονται από Google Fonts. Αν το κοινό σας είναι σε κινητό με
   αργό δίκτυο, κατεβάστε τα δύο woff2 τοπικά και αντικαταστήστε το `@import`.
5. **A/B test** στον τίτλο: «Η φωτιά διπλασιάζεται κάθε 30 δευτερόλεπτα» έναντι μιας παραλλαγής
   με το κόστος («Μια φωτιά κουζίνας κοστίζει X — η πρόληψη 34,90 €»).

## Δημοσίευση

Στατικό αρχείο: ανεβαίνει ως έχει σε Netlify (drag & drop), Vercel, GitHub Pages,
Cloudflare Pages ή σε απλό cPanel hosting μέσω FTP.

## Ροή πληρωμής

Η φόρμα **δεν** δέχεται αριθμούς καρτών — και δεν πρέπει ποτέ να δεχτεί: η συλλογή στοιχείων
κάρτας σε δική σας σελίδα σας υπάγει στο πλήρες PCI-DSS. Η ροή είναι:

1. Ο πελάτης συμπληρώνει διεύθυνση παράδοσης και email.
2. Η παραγγελία στέλνεται στο `ORDER_ENDPOINT` (ή ετοιμάζεται ως email όσο αυτό είναι `null`).
3. Ο πελάτης πατά «Πληρωμή … με κάρτα» και μεταφέρεται στο `PAYMENT.checkoutUrl` του παρόχου.
4. Ο πάροχος επιβεβαιώνει τη χρέωση· εσείς στέλνετε το email επιβεβαίωσης.

Αν ο πάροχός σας δίνει δυναμικό ποσό ανά παραγγελία, περάστε το σύνολο στο URL από τη
`finish()` (π.χ. `?amount=${s2.total}`) ή δημιουργήστε session πληρωμής από το backend σας.
